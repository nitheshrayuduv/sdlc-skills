## Engineering Build: before

Read `.specify/presets/engineering-build/guide/rules.md` and follow it. When the core steps below are done, do the **Engineering Build: after** section at the end of this command before your final report.

Read the feature request and relevant repository boundaries. Carry forward user goals, compatibility, sensitive data, constraints and observable acceptance criteria. Do not select an older feature, write technical design, or decide product questions for the user; the core steps below create and identify the new feature. Apply the **Specify** guidance in the stage map.

{CORE_TEMPLATE}

## Engineering Build: after

Use the feature directory the core steps created; never choose the newest folder.

Read spec.md. Check user needs, scope, compatibility, sensitive data and measurable acceptance criteria against the request and source evidence. Preserve IDs and accepted decisions. Improve wording and simple links where meaning is unchanged. Record unresolved product questions in its clarification area. Do not invent answers, impose architecture, or create plan.md or tasks.md. Do not create a separate engineering specification.

Report remaining decisions and the next valid stage in plain English. Do not label the specification ready while a material product decision is unresolved.
